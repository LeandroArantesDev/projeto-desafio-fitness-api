ESTRUTURA DO PROJETO - projeto-desafio-fitness-api
====================================================

API REST em Java (Servlets) com arquitetura em camadas (padrao MVC):
Controller (rota HTTP) -> Service (regra de negocio) -> DAO (acesso a banco)
-> Model (dados). Nao ha telas aqui: todas as respostas sao JSON. O front
end fica em outro projeto e consome esta API por HTTP.

Fluxo de uma requisicao:
  Request HTTP -> AuthFilter -> Controller -> Service -> DAO -> MySQL
                      |             |            |
                      v             v            v
                 valida token   le/responde   valida regras
                 JWT            JSON + status


src/main/java/com/fitness/
----------------------------
model/
    Usuario.java, Desafio.java, Participacao.java, Progresso.java
    Apenas os dados (getters/setters), sem logica. Representam as tabelas
    do banco. Os nomes dos atributos (snake_case) sao os nomes dos campos
    no JSON.

dao/
    UsuarioDAO.java, DesafioDAO.java, ParticipacaoDAO.java,
    ProgressoDAO.java, MysqlDAO.java (classe base)
    Apenas SQL puro (SELECT/INSERT/UPDATE/DELETE) e conversao de
    ResultSet para objeto. Nenhuma validacao ou regra de negocio aqui.

service/
    UsuarioService.java, DesafioService.java, ParticipacaoService.java,
    ProgressoService.java
    Regra de negocio: validacoes, autenticacao, senha minima, e-mail
    unico, calculo de progresso, etc. Chama o DAO. Nunca lida com
    HttpServletRequest/Response.

controller/
    UsuarioServlet.java, DesafioServlet.java, ParticipacaoServlet.java,
    ProgressoServlet.java, LoginServlet.java, RegisterServlet.java,
    BaseServlet.java
    Ponte entre a rota HTTP e o Service. Le o JSON do corpo e o id da
    URL, chama o Service e responde JSON com o status HTTP correto
    (200, 201, 204, 400, 401, 403, 404, 500).
    BaseServlet e a classe base: so tem metodos utilitarios genericos
    (lerJson, responderJson, responderErro, extrairId, usuarioLogadoId,
    paramLong), sem regra nenhuma.

filter/
    AuthFilter.java
    Intercepta todas as requisicoes /api/* antes do Servlet. Libera
    /api/login e /api/register; nas demais exige o header
    "Authorization: Bearer <token>" e valida o JWT. A rota /api/usuarios
    so e liberada para administradores. Mexer aqui apenas para regras
    globais de autenticacao/seguranca.

config/
    MysqlSingleton.java
    Conexao unica com o banco de dados (padrao singleton). Mexer apenas
    se mudar a configuracao de conexao.
    JwtUtil.java
    Gera e valida os tokens JWT (validade de 2 horas).


src/main/webapp/
-----------------
WEB-INF/web.xml
    Configuracao do servlet container.


Pastas que NAO devem ser editadas manualmente
----------------------------------------------
target/   -> gerado automaticamente pelo Maven ao compilar (mvn compile/
             package). Qualquer edicao manual e perdida no proximo build.
deploy/   -> artefato de deploy (WAR). Mesma logica do target/,
             nao e codigo-fonte.

Ambas as pastas estao no .gitignore e nao devem ser versionadas no Git.


Outros arquivos na raiz
------------------------
database.sql       -> script de criacao/estrutura do banco de dados.
docker-compose.yml -> sobe o ambiente (MySQL + Tomcat) via Docker.
pom.xml            -> configuracao do Maven (dependencias, build).
README.md          -> como rodar e documentacao dos endpoints.

Regra geral: cada camada so fala com a camada de baixo dela
(Controller -> Service -> DAO). Nunca pular camada (ex: Controller
chamando DAO direto).
